# MedPal 医院宣传信息管理系统 V1.2.1

**仓库地址**：https://github.com/zjmnt1992/MedPal

> ⚠️ **部署提示**：因医院信息安全要求，不建议公网部署；无内网 DNS 可关闭 Nginx 部署。
> ⚠️ **容量建议**：本系统结构轻量且简单，适合服务器存储资源紧张的单位使用，总用户数不建议超过 3000，并发不建议超过 50。

基于 Python FastAPI + React + SQLite 的轻量化医护信息管理系统：内置完整权限体系（50 个权限点）、三级变更审核、标识台账与平面打点、单位级功能开关、通知中心与自动运维能力，开箱即用、无需复杂数据库迁移。

---

## 📌 核心功能

- **人员全流程管理**：医护行政人员统一建档、在职/离职状态管控、工号唯一不可修改；形象照（正面/侧面）上传支持按角色独立授予/回收「照片上传」权限（本人自助上传不受限）；离职满 180 天自动站内信提醒超管清理账号，档案仅保留统计口径
- **分级审核机制**：变更提交即时生效 + 追认审核；免审 / 科室级 / 超管级三级字段权限，同科室负责人或签、禁止自审；24 小时未审提醒、72 小时自动升级超管；驳回回滚（带并发冲突检测）
- **RBAC 精细化权限**：**50 个权限点、12 个权限分类**，科室 / 工种双向数据隔离（个人 / 管辖 / 全局三种数据范围），内置超级管理员、科室管理员、普通员工三类角色
- **科室与标识管理**：科室信息与特色设备管理；院区 → 楼栋 → 楼层 → 区域四级平面打点；标识台账、二维码、巡检、维修记录、临期/超期/状态异常预警看板、批量导入导出
- **单位级功能开关**：站内信、标识平面与标识设置、制度牌三个模块可按单位一键启停（默认全部启用），关闭后菜单隐藏且接口返回 403，历史数据保留
- **通知中心**：16 个业务事件、6 个分组，支持按事件配置启停、标题/正文模板与收件人范围（角色 / 科室 / 权限 / 自定义规则），全站站内信 + 顶部消息铃铛
- **制度与数据管理**：制度版本管控与历史快照留存、Excel 批量导入导出、图片打包下载
- **注册与账号审核**：自助注册可开关 + IP 限流风控，超管可审全部、科室管理员仅可审管辖科室的申请；新建账号初始口令由「账号设置」模板生成
- **智能运维能力**：启动自动建表 / 自动补列、数据库自愈、每日自动备份、孤儿文件与过期数据清理、日志自动轮转、磁盘与库大小监控告警、每月 VACUUM
- **安全防护体系**：双 Token 认证、登录/刷新/注册限流、bcrypt 密码哈希、Token 黑名单、操作审计日志、富文本内容清洗

## 🚀 快速启动（本地开发）

**环境要求**：Python 3.11+、Node.js 18+

### 1. 初始化配置

```bash
# 复制环境变量配置
cp .env.example .env

# 生成安全密钥（必须替换默认值，否则无法启动）
python -c "import secrets; print(secrets.token_urlsafe(64))"
```

### 2. 启动后端

```bash
pip install -r requirements.txt
cd backend && python run.py
```

- 后端地址：http://localhost:5000
- 接口文档：http://localhost:5000/docs

### 3. 启动前端

```bash
cd frontend && npm install && npm run dev
```

- 前端地址：http://localhost:5173

### 4.（可选）导入演示数据

```bash
cd backend
python seed_demo.py --buildings 4 --staff 30 --signages 60
```

脚本为幂等设计（只补齐差额，不删除不覆盖），生成的数据统一标记 `created_by/updated_by = seed_demo`，便于识别与清理。

## ⚙️ 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `SECRET_KEY` | 无（**必填**） | JWT 签名密钥，仍为内置默认值时应用拒绝启动 |
| `ENVIRONMENT` | `development` | `development`（日志更详细）/ `production` |
| `APP_NAME` | MedPal信息管理系统 | 应用名称（可在「单位设置」中改系统名称） |
| `DATA_ROOT` | 自动检测 | 数据根目录；源码布局取项目根 `data/`，容器布局取 `/app/data` |
| `DATABASE_URL` | 空 | 留空则使用 `${DATA_ROOT}/medical.db` |
| `SQLITE_WAL_ENABLED` | `true` | Linux 生产建议开启；Windows Docker 挂载 NTFS 卷需设为 `false` |
| `CORS_ORIGINS` | `http://localhost:3000` | 允许的跨域来源，逗号分隔（本地开发需包含前端地址） |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | `15` | 访问令牌有效期 |
| `REFRESH_TOKEN_EXPIRE_MINUTES` | `60` | 刷新令牌有效期 |
| `REMEMBER_ME_REFRESH_TOKEN_EXPIRE_DAYS` | `3` | 「记住我」刷新令牌有效期 |
| `UPLOAD_MAX_SIZE_MB` | `20` | 单文件上传大小上限 |
| `UPLOAD_ALLOWED_TYPES` | `image/jpeg,png,gif,webp` | 允许上传的文件类型 |
| `BACKUP_ENABLED` | `true` | 是否启用每日自动备份 |
| `BACKUP_MAX_COUNT` | `7` | 备份保留数量（每日 1 份 = 最近 7 天） |
| `LOG_LEVEL` | `INFO` | DEBUG / INFO / WARNING / ERROR |

## 🧩 权限体系与功能开关

### 权限分类（角色管理中按此分组授权）

| 分类 | 权限点数 | 主要权限项 |
| --- | --- | --- |
| 人员管理 | 8 | 查看 / 新增 / 修改 / 删除人员、修改状态、审核人员变更、查看离职人员、照片上传 |
| 科室管理 | 4 | 查看 / 新增 / 修改 / 删除科室 |
| 制度管理 | 4 | 查看 / 新增 / 编辑 / 删除制度 |
| 标识平面 | 9 | 标识增删改查、标识标记、预警、巡检、导入导出、维修记录 |
| 标识设置 | 4 | 平面设置、院区管理、标识分类、供应商设置 |
| 用户管理 | 6 | 用户增删改查、重置密码、账号审核 |
| 角色管理 | 4 | 角色增删改查 |
| 数据管理 | 2 | 数据导出、数据导入 |
| 系统管理 | 3 | 系统配置、数据备份、审计日志 |
| 系统设置 | 2 | 功能开关、通知设置 |
| 特殊功能 | 1 | 上传工卡照片 |
| 站内信 | 3 | 查看 / 发送 / 群发站内信 |

### 两层门禁模型

1. **单位级功能开关**（系统设置 → 功能开关）：站内信、标识平面与标识设置、制度牌，控制整个单位是否启用，关闭后菜单入口隐藏、相关接口返回 403，历史数据保留；
2. **角色级权限点**（角色管理）：控制哪些角色可访问，与功能开关**都通过**才放行。

> 升级策略：程序启动时自动补齐数据库结构与缺失权限点，并为存量角色回填新增权限（仅回填一次，之后由管理员在角色管理中自行调整），重启不会覆盖人工配置。

## 💾 数据与运维

- **数据目录隔离**：数据库、上传附件、备份、日志、公开资源统一存放 `data/` 目录，与代码分离，升级/重建容器不丢数据
- **自动备份**：每日北京时间 00:15 自动备份，默认保留最近 7 天（`BACKUP_MAX_COUNT` 可调），支持手动备份与恢复；每次恢复前自动生成 `prerestore` 回滚点（保留 7 天）
- **自动清理**：孤儿上传分片（24 小时）、临时导出包（1 天）、标识附件导出包（24 小时）、已读站内信（30 天）、未读站内信（90 天）、过期 Token 黑名单与限流记录（每小时）、运行日志（保留当天 + 6 天历史）
- **数据库维护**：每月 1 日自动执行 VACUUM 回收空间；WAL 超过 50MB 自动 checkpoint
- **监控告警**：数据库文件超过 500MB 警告、超过 1000MB 严重，磁盘空间不足同样告警，通过站内信通知管理员（同级别告警 6 小时内不重复推送）

## 🛡️ 核心安全特性

- 强制密钥校验、bcrypt 密码加密、首次登录改密、口令模板强度校验
- HttpOnly 刷新 Token、Token 黑名单、防 XSS 与越权、富文本服务端清洗
- 登录 / 刷新 / 注册三档 IP 限流（登录 10 次/分钟、注册 5 次/小时，超限自动封禁），限流记录持久化到数据库，多进程共享、重启不失效
- 文件上传类型与大小校验、分片上传会话管理、备份文件名白名单
- 全链路操作审计日志（含导入导出、备份恢复、权限变更等敏感操作）

## ❓ 常见问题

| 问题 | 说明 |
| --- | --- |
| 忘记密码 | 超级管理员在用户管理后台重置 |
| 系统升级 | 直接重启服务，程序自动更新数据库结构并补齐权限点，无需手动迁移 |
| 待审提示 | 正常追认审核机制，修改即时生效，超时自动升级审核人 |
| 磁盘占用 | 系统自动清理冗余文件，备份、日志、站内信均有过期清理策略 |
| 菜单看不见 | 先看「功能开关」是否开启（单位级），再看「角色管理」是否授予对应权限（角色级） |
